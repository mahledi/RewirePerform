# RewirePerform Study Layer Phase 2

RewirePerform already captures enough operational data for internal program
evaluation: adherence, completed days, check-ins, comprehension, journals as
counts, program progress snapshots, validated assessment timing, and team-level
aggregate readiness.

This is a strong launch foundation, but it is not yet a full study platform.
The next layer should turn usage into a privacy-safe, presentation-ready
evaluation system without medical or diagnostic claims.

## Current Evidence Foundation

The system can already support:

- team-level adherence and completion
- daily Team Pulse participation and averages
- comprehension completion and correctness rates
- journal participation counts without journal text
- Pre/Mid/Post readiness counts
- program instance scoping
- QA cohort separation through `is_test_user` and `is_test_team`
- coach aggregates with `n >= 5`
- admin presentation exports without private text

Safe claim language:

- observed development
- program activity
- adherence
- completion
- team-level patterns
- internal program evaluation

Avoid:

- diagnosis
- treatment claims
- brain rewiring proof
- clinical study language
- causal claims without a control group

## Current Limitations

These are not launch blockers, but they matter for serious presentations and
future research quality:

- There is no formal cohort registry yet.
- There is no locked baseline snapshot per cohort.
- QA, demo, pilot, and production users are separated only by flags, not by a
  structured study design.
- There is no export manifest that records exactly which data version powered a
  presentation.
- There is no dropout or missingness analysis.
- There are no effect sizes or confidence intervals.
- No control group or comparison group exists.
- Progress snapshots are operational snapshots, not a formal longitudinal study
  table.
- Auth users cannot be migrated between Supabase projects without a deliberate
  migration strategy.

## Phase 2 Data Model

Add a dedicated study layer rather than overloading operational tables:

- `study_cohorts`
  - cohort name, sport, level, start date, organization, status
  - flags: pilot, launch, internal, demo, qa

- `study_participants`
  - user id, cohort id, team id, role
  - consent status
  - anonymized participant key
  - inclusion/exclusion flags

- `study_measurement_windows`
  - baseline, mid, post, follow-up
  - planned date range
  - actual completion counts

- `study_aggregate_snapshots`
  - cohort-level adherence
  - check-in participation
  - comprehension rate
  - assessment change
  - missingness/dropout
  - generated_at and source version

- `study_export_manifests`
  - export id
  - generated by
  - cohort
  - included tables
  - privacy level
  - claim boundary

## Phase 2 Metrics

Operational metrics:

- activation rate
- day-1 completion
- 7-day active rate
- 28-day active rate
- 56-day completion
- average completed days
- streak distribution
- journal participation count
- comprehension completion and average score

Development metrics:

- validated Pre/Mid/Post assessment change
- Rewire Development Index change
- team-level Team Pulse trends
- pressure, focus, recovery, and team connection aggregate trends

Study-quality metrics:

- `n`
- missingness
- dropout
- low-confidence flags
- pre/post paired sample count
- effect size where appropriate
- confidence intervals where appropriate

## Privacy Rules

The study layer must never export:

- journal text
- free reflections
- raw individual check-ins
- raw questionnaire answers
- individual psychological scores
- player-identifying development labels

Allowed:

- anonymized participant keys for internal analysis
- team/cohort aggregates
- counts
- rates
- validated assessment aggregate changes
- low-confidence flags

Coach-facing rule remains stricter than admin research export:

- coach sees only team aggregate from `n >= 5`
- no raw private text
- no individual histories

## Launch Recommendation


After first real pilot usage, build Phase 2 as a dedicated branch:

1. Add cohort registry.
2. Add export manifests.
3. Add missingness/dropout reports.
4. Add paired Pre/Post aggregate analysis.
5. Add presentation dashboard for cohort-level evidence.
6. Add a clean independence path for migrating from Lovable Cloud to owned
   Supabase infrastructure.

The current foundation is strong enough to launch with careful wording. The
Phase 2 layer is what turns RewirePerform from a strong product into a serious
long-term evidence engine.
